## Accepted-output audit

Across both splits, accepted answers consistently preserve explicit dates/relative clocks, numbers, counterfactual and fictional scope, source-report attribution, rejected disposition, and named action agents. Russian outputs contain no untranslated generic role/status labels. I found no accepted fabricated concrete value or unsafe promotion.

Three accepted-content limitations remain material to honest reporting:

1. In development alternatives run 1, retention translates source `обсуждаю` as `is considering`; accepted answers generally repeat considering. This preserves the alternatives and uncertainty but may omit the source's communicative activity. It is a disputed translation/coverage loss, especially because the question asks what Ada discussed.
2. Development fiction run 2 retains only the proposal to discuss the fictional example. Produced answers based on that record can be faithful yet cannot supply the requested handle-replacement promise. They should count as usefulness misses even when non-null, not as source-entailment errors.
3. Development `v17-held-assistant` run 1 has three accepted source-word-sense errors. The original says `не проверенное условие` in a contract/service context: an unverified condition or contractual term. The retained English `not a verified condition` preserves that sense. EN-query→RU inferred renders it as `не подтверждённое состояние`; EN→RU explicit says `не было подтверждённым состоянием устройства`; RU→RU explicit says `не подтверждённое состояние устройства`. `Состояние устройства` means the device's physical/state condition, a different proposition from a service-contract condition. All three answers remain tentative, assistant-attributed and unverified, so this is not lost uncertainty or a wrong-language failure; it is an accepted source-entailment/action-object error. The RU-query→RU inferred row omits the condition clause and does not make this mistranslation.

The nested-report measurement/non-replacement attachment remains the disputed interpretation documented in the selected forensic review: complete source context supports it as Ada's clarification of the same Bo report, while the generated syntax places it inside Bo's paraphrased complement. It remains fully attributed and unverified, so I do not classify accepted answers as factual promotion.

## Small coherent next change

The dominant failures are representation and comparison boundaries, not missing safety checks. A coherent next revision should make four bounded changes without changing models, gates, call counts, or adding semantic retries:

1. **Separate discourse-record metadata from embedded durable actions.** Generation should preserve explicit source activity/agent when material, but verification should not demand identity of incidental record/stated/described framing verbs when the embedded proposition and agency are unchanged. Apply the distinction symmetrically to retention and answers. Keep strict rejection for changed embedded acts such as proposed→completed, considering by Ada→considering by someone else, or passive removal of a material proposer/nonselector.
2. **Make proposal dimensions explicit in generation.** An asserted statement can describe a proposed disposition with tentative timing. Generation should not lower `commitment` merely because `temporal.status` is tentative, and repair feedback should name the three fields separately. This directly addresses development undated run 2.
3. **Parse compositional clock and negated schedule structure.** Recognize Russian `week after an undated record` as a source anchor, and prevent negated `not booked` from activating an actual-schedule/time-envelope requirement. Keep source-anchor plus unknown-clock conjunction and semantic verification unchanged.
4. **Make ownership choices structurally representable.** Replace the static outcome/free-`target_id` combination with a dynamic enum of supplied eligible profile tokens plus explicit `proposed` (only when admitted) and `uncertain`. Preserve the same ownership semantics and single call. The existing trace should continue to acknowledge that provider raw output is unavailable, so this prevents invalid combinations rather than claiming to diagnose the historical one.

The same next scope should strengthen lexical sense and attachment inside the existing proposition/action comparison. Generation and verification must resolve a translated relational noun from its governing frame: a condition associated with an unstudied contract or service requirement remains a contractual condition/term, while a device's physical state requires explicit physical-state support. This should be framed as a general source-context word-sense obligation with English/Russian contrastive tests, not an allowlist for `условие`. It needs no new verdict dimension, model call, retry, or language-identity rule; these three answers are fluent Russian and should fail source entailment instead.

Repair should continue to preserve position obligations and receive no semantic retry. The evidence does not support loosening whole-source absence, action-object, fiction, counterfactual, or attribution guards.
