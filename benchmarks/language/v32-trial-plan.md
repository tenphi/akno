Code review found that larger audit batches would exceed configured model-role output ceilings. Retention therefore checks at most two disjoint candidates per first-pass call, and answers check one block per call. Each candidate/block is submitted only once; rejection never triggers retry. The complete source and related-candidate relation context remain available, and every answer block keeps its own citations and original id. A malformed or unavailable batch withholds the operation. Final retention also withholds records whose internal relation targets were rejected, including transitive dependents. Usage and latency receipts sum actual calls while preserving unknown usage; configured ceilings remain unchanged.

Every returned repair index must survive as a candidate or an explicit hold; a duplicate collapse invalidates the transaction and preserves already admitted candidates.
