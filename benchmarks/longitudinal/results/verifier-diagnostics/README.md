# Content-safe retention verifier diagnostics

This is an invented, exposed development corpus with source-author review of all returned records.
It is not independent review or a population-accuracy estimate. The baseline uses released 0.18.11;
the candidate adds diagnostics without changing prompts, source context, admission, model budgets or
retry behavior. Each file contains all eight cases and both repetitions, with no replaced coordinates,
pooled receipts or cherry-picked repetitions. Corpus/runner hashes bind the frozen checks; raw calls
remain private because provider exceptions are not safe publication artifacts.

The five useful native cases cover a long receipt, corrected travel schedule, pending debit, tentative
arrival and a disputed multilingual forwarded report. A sixth native case is an ephemeral rerun request.
Two injected first-generation proposals expose unsupported completion and ownership. Their four
scripted extraction outputs are **not live calls**; zero/null extraction telemetry for these rows belongs
to those fixtures. Later structural repair and independent verification remain real model calls.

The preset completion-control label says “semantic hold, never delivered fact”. Existing pre-verification
structural repair instead replaces the unsupported completion with a qualified source-supported estimate
in both repetitions of both cohorts. These are safely narrowed proposals, not semantic holds or acceptance
of the original completed-delivery claim. The author/owner controls are valid semantic refusals in both
repetitions. No unsupported completion or ownership is returned. All four native process commands are
omitted across the separate cohorts.

Native useful coordinates return in 5/10 baseline cases (six records) and 7/10 candidate cases (nine
records). All eight baseline and eleven candidate returned records, including narrowed controls, were
checked against the source and preserve supported report scope, pending/scheduled status and temporal
qualification. This stochastic difference is **not a demonstrated useful-coverage improvement**: the
feature adds observability, not semantic permission. The candidate still has five unavailable/invalid
native records across three failed batches: two `time_witness_invalid` and one
`context_witness_invalid`. Nonexact/expanded or ellipsis-containing deciding excerpts remain invalid;
source-witness failures are not automatically retried. Useful false holds and targeted recovery remain
#217/#219. The historical partial digest's missing diagnostics cannot be inferred from these new controls.

Only gpt-6-luna makes live language-model calls. The installed maintenance role has a retention-specific
600000 ms timeout, no separate role output ceiling and provider-default reasoning. The existing retention
allowance is 32768 tokens, concurrency four and opt-in batch failure scope. Complete source context remains
in each deciding request; there is no source partition or context reduction. Per-request serialized input
size, call time, complete-source presence, verifier wall time and aggregate latency are recorded separately.
These small cases generally use one verifier batch and do not establish a concurrency speed improvement;
deterministic fixtures cover multiple launched batches and source-wide early termination.

All actual calls report primary usage and request counts; unknown usage would remain unknown, not zero.
Cached/reasoning detail is recorded as input/output subsets, not added to total usage. The numerical
variation does not demonstrate reduced overhead. Every candidate batch receipt was checked against the
original settled model outcome; failed batches preserve their paid usage. No provider error, prompt,
response, quotation or schema-issue detail enters the new runtime diagnostics. The published invented
source/returned prose here is review evidence, not the production diagnostic payload.

Three review/fix rounds cover receipt propagation (including early preservation/correction holds),
parallel versus serial launched-candidate classification, exact set/grounding failure codes, content safety,
semantic refusal, known/unknown usage, source atomicity and dependency closure. The complete local gate
passes build, lint, dead-code checks, 4899 tests, model-free and installed-package smokes, documentation,
formatting and repository safety. Integration checks persist/replay diagnostics through restart and prove
`retry_failed` does not rerun completed partial or semantic receipts. Historical optional-field and older
consumer stripping behavior are checked. Published-release verification and a fresh repeated cohort are
separate from these prepublication receipts.
